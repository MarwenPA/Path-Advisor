Différences mobile vs desktop — tests de validation

  • Container 1080 px max (mobile = full-width). Bumpé depuis 960 sur retour utilisateur pour donner plus d'air aux appréciations longues. Reste sous le plafond 1200 du design system (UX spec § Layout).
  • Bulletin meta + warning INLINE horizontal : sur mobile c'est stacked vertical, sur desktop la place permet de mettre le warning summary à droite (gain ~80 px vertical, plus de matières visibles above-the-fold).
  • Note en display-3 (28 px) : sur mobile elle était body 16 px. Desktop = profite de l'espace pour donner du poids visuel au chiffre (ergo Doctolib). Reste tabular-numbers pour alignement vertical entre lignes.
  • Appréciation NON tronquée : sur mobile -webkit-line-clamp 2 (place limitée). Desktop = max-width 640 px, naturel jusqu'à 3-4 lignes. Sarah peut tout lire sans tap.
  • Footer primary right-aligned : convention UX spec § Form Patterns desktop. Width min 220 px pour visibility, pas full-width (non nécessaire ici).
  • Tab "+ Ajouter un bulletin" avec label plus explicite que mobile ("Ajouter" seul). Place suffisante en desktop.
  • Kbd hints en edit mode (Scène B) : <kbd>Entrée</kbd> et <kbd>Échap</kbd> stylés en pill — convention desktop power-users. Sur mobile, simple texte sans pills (clavier physique rare).
  • Touch / hover : les actions edit/delete restent visibles toujours (cohérence mobile). Hover desktop ajoute background subtil sur la ligne entière (`color-bg-3`).
  • Test parité mobile/desktop : ouvre le 2-3-recap-editor.html à côté. Structure stricte identique : tabs → bulletin meta → matières → add btn → primary. Seuls les details horizontaux changent.
  • Test responsive intermédiaire (768 px) : le container devra graduellement passer de 960 desktop → 600 (form) → full-width (mobile). À tester en redimensionnant la fenêtre.
