Tests de validation visuelle

  • Matières pré-remplies par niveau (Scène A) : Sarah Terminale général voit tronc commun (Français Bac anticipé, Philosophie, Histoire-Géo, Anglais, Espagnol, EPS, Ens. scientifique) + ses 3 spés (Maths, SVT, HGGSP). Référentiel adapté selon Story 2.2 niveau + filière + spés.
  • Saisie partielle OK (Scène A) : 5/10 matières remplies, autres en placeholder —,— / 20. Bouton "Valider et continuer" toujours enabled (au moins 1 matière suffit pour commit, cf Story 2.4 AC5). Anti-paywall implicite.
  • Pas d'astérisque "obligatoire" : aucun champ marqué required avec * rouge. Les matières sont toutes optionnelles, l'utilisateur décide combien remplir (UX spec § Form Patterns).
  • Validation on blur seulement (UX-DR35) : aucune validation à chaque keystroke. L'erreur Scène C n'apparaît qu'après que l'utilisateur quitte le champ avec une valeur invalide.
  • Format français accepté : notes affichées avec virgule (14,5) — normalisé en . côté serveur. inputmode="decimal" active le clavier numérique mobile.
  • Appréciation facultative et repliée (Scène A/B) : bouton tertiary "+ Ajouter une appréciation" replie par défaut. Tap → expand Textarea 3 lignes (Scène B). Densité visuelle réduite, l'élève qui veut juste taper des chiffres le fait vite.
  • Breadcrumb fallback OCR (Scène B) : seulement si origin=ocr_fallback. Bandeau discret text-caption avec icône retry + ton calme ("Pas grave, on continue à la main"). Désactivable au scroll (disparaît dès premier scroll).
  • Référentiel adapté niveau collège (Scène B Mehdi) : 3ème → matières collège (Maths, Français, Techno, Histoire-Géo, EPS, etc.), pas lycée. Cohérent getSubjectsForLevel Story 2.4 T1.
  • Erreur inline sous champ (Scène C, UX-DR35) : bordure color-danger + texte error color-danger + icône warning. Pas de toast ambient. La valeur invalide est CONSERVÉE dans le champ (pas effacée auto), l'utilisateur la corrige.
  • Lien tertiary "Plus tard" footer (Scène A) : sortie élégante sans repasser par l'écran 3 cards AC1. Déclenche Story 2.5 (mode postponed). Visible en permanence, jamais en CTA principal.
  • Tabs trimestres avec ajout libre : bouton "+ Ajouter" tab pour 4e trimestre (rare en lycée FR, mais possible). Drafts séparés par trimestre en localStorage (cohérent Story 2.4 AC7).
  • Bouton supprimer matière (icône ✕) : visible toujours sur mobile (pas seulement au hover — anti-discrimination touch). À droite, 32×32 px touch target. Tap → toast "Annuler" 5 s (Story 2.4 AC3).
  • Test focus a11y : Tab order : back → tabs → bulletin label edit → champ matière 1 → bouton "+ Ajouter appréciation" matière 1 → bouton supprimer matière 1 → champ matière 2 → … → "+ Ajouter matière manquante" → primary "Valider" → "Plus tard" tertiary. Focus ring 2 px brand.
  • Mobile keyboard "Suivant" : sur iOS, le bouton "Suivant" du clavier numérique passe au prochain champ note (skip les boutons appréciation et supprimer) — UX power-user pour saisie rapide successive.
  • Test reduced motion : pas d'animation expand appréciation (hauteur transition à 0 ms). Aucune autre animation.
  • Test sentiment sortie écran : à la fin, l'élève pense quoi ? Cible : "OK, c'était pas si long en fait." — pas "J'aurais préféré scanner." Cohérent §4.2 Story 2.4 état émotionnel.
