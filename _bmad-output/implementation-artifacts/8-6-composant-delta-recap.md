# Story 8.6 — Composant `DeltaRecap` : écran « voici ce qui a bougé »

Statut : review · Epic 8 (continuité temporelle & notifications) · 2026-09-26

## 1. User Story

As a élève qui revient à J+30, I want voir un écran d'accueil qui me montre ce qui a bougé depuis ma dernière visite, So that ma session démarre sur du delta, pas sur l'écran neutre (UX-DR14 + UX-DR29).

ACs (epic-8) : cartes réponse-école (avec stat avant/après), nouvelles-écoles (compteur), calendrier Parcoursup (daysUntil + préparation) ; état stable = pas d'écran vide (rien ne s'affiche) ; interstitiel plein écran à J+1+, 1 CTA primary par carte, bouton « Tout vu, continuer » vers le dashboard (8.8 `/accueil`) ; ton calme (pas de confetti), delta négatif cadré constructif.

## 2. Décisions de périmètre

1. **Référence temporelle = curseur dédié, pas `last_login`.** Le login allauth met `last_login` à jour *au moment du login* — au premier GET du recap, la référence serait déjà « maintenant » et le delta toujours vide. Nouveau modèle `DeltaRecapCursor` (OneToOne user, `seen_at`, RLS calquée sur `notification_preferences`) dans l'app `notifications` (l'in-app est l'autre canal de la continuité temporelle d'Epic 8 — même app que les emails).
2. **Sémantique du curseur** : premier GET sans curseur = pose de la baseline à `now` et zéro carte (un compte neuf n'a pas de « depuis ta dernière visite » ; sans cette pose, un utilisateur quotidien n'aurait JAMAIS de baseline et un retour à J+30 scannerait tout l'historique). GET suivants : cartes calculées depuis `seen_at` seulement si `seen_at` ≤ now−24 h (règle J+1 de l'AC) — sinon liste vide. **ACK explicite** (`POST /ack`) → `seen_at = now` : déclenché par « Tout vu, continuer » ET par tout clic CTA (naviguer via une carte = l'avoir vue) ; fermer l'onglet sans ack ⇒ le recap re-propose les mêmes deltas au retour suivant (non-vu = toujours de l'actualité).
3. **Copy générée côté backend** (service `delta_recap.py` → cartes `{kind, title, body, cta_label, cta_url, …}`) pour que le lint de ton reste **exécutable en Python** comme 8.3/8.4/8.5 — le front ne fabrique aucune phrase. C'est aussi la préparation directe de 8.7 (« le même composant alimente email et app ; seul le rendering layer change ») : la carte calendrier expose déjà `{jalon, days_until, recommended_actions[]}` depuis `MILESTONE_COPY` (8.3), source unique.
4. **Delta négatif : lexique 8.4, pas l'exemple littéral de l'AC.** L'AC illustre « INSA Lyon a refusé — voici 3 alternatives » mais `\brefus` est un marqueur BANNI par le lint 8.4 (conformité émotionnelle, décision déjà actée). La carte `not_aligned` reprend le cadrage diplomatique 8.4 (« profil non aligné aujourd'hui », alternatives) avec CTA « Explorer d'autres écoles » → `/schools`. Déviation volontaire, consignée ici.
5. **Cartes** : une carte par réponse école depuis `seen_at` (stat avant/après lue sur `AdmissionStat.previous_proba/expected_proba` posées par 5.8 quand `outreach_delta_applied_at` ≥ seen_at) ; UNE carte agrégée nouvelles-écoles (réutilise `_signal_overlap`/`OVERLAP_MIN` de 8.5 — même définition de « pertinente », jamais l'ai-service) ; UNE carte calendrier = prochain jalon dans sa fenêtre `notify_days_before`. CTAs de l'AC : « Voir le parcours mis à jour » → `/mes-envois/{id}`, « Voir les nouvelles écoles » → `/schools`, « Préparer mes vœux » → `cta_path` du jalon.
6. **Front** : `DeltaRecapInterstitial` (client) monté dans `/accueil` (8.8 le prévoit : plein écran AU-DESSUS de la home ; « Tout vu, continuer » démonte et révèle la page). `role="dialog"` + `aria-modal`, focus initial, zéro emoji/confetti. État stable : le composant ne rend rien (AC « redirection silencieuse » = la home est déjà dessous).

## 3. Périmètre technique

- API : `GET /api/v1/me/delta-recap/` → `{cards: [...]}` ; `POST /api/v1/me/delta-recap/ack/` → 204. Authentifié étudiant, RLS via GUCs de session.
- Nouveaux fichiers : `notifications/delta_recap.py` (service + copy), migration `0005_deltarecapcursor` (+ RLS), vues/URLs, `tests/test_delta_recap.py` ; front `components/delta-recap/DeltaRecapInterstitial.tsx` (+ test), `lib/api/delta-recap.ts`, intégration `/accueil`.
- Tests backend : baseline premier GET, règle 24 h, carte réponse (avant/après), carte nouvelles-écoles (overlap), carte calendrier (fenêtre), ack, lint de ton (bannis 8.3 + 8.4 sur toutes les cartes), RLS isolation.

## 4. Résultats (implémentation)

**Livré.**

- **Backend** : `DeltaRecapCursor` (OneToOne user, `seen_at`) + migrations 0005/0006 (RLS calquée sur `notification_preferences`, garde vendor SQLite) ; service `delta_recap.py` — toute la copy y est construite (lint de ton exécutable) ; `GET /api/v1/me/delta-recap/` (baseline au premier appel, règle 24 h, **GET ne déplace jamais le curseur**) ; `POST /ack/` (204, idempotent). Cartes : réponse école (une par réponse, stat 5.8 `previous_proba→expected_proba`, `not_aligned` au lexique 8.4 diplomatique + CTA `/schools`), nouvelles écoles (agrégée, `_signal_overlap`/`OVERLAP_MIN` de 8.5, accord singulier/pluriel), jalon Parcoursup (fenêtre `notify_days_before`, `days_until` + `recommended_actions` de `MILESTONE_COPY` — la forme 8.7).
- **Frontend** : `DeltaRecapInterstitial` (client, `role="dialog"` `aria-modal`, focus initial, Escape=dismiss) monté dans `/accueil` — fetch serveur en `Promise.allSettled` (échec ⇒ pas d'interstitiel, la home n'est jamais otage) ; état stable ⇒ rend **rien** ; « Tout vu, continuer » et chaque CTA ackent (fire-and-forget) ; chrome dans `fr.json#deltaRecap`, les phrases viennent du backend.
- **Tests** : 11 backend (`test_delta_recap.py` — baseline, 24 h, GET-ne-bouge-pas/ack-bouge, anonyme 401, carte réponse avec avant/après, not_aligned constructif, comptage overlap + accord singulier réel [école désactivée], fenêtre jalon, état stable, lint de ton sur les 3 kinds + table `_RESPONSE_COPY` entière) + 1 RLS isolation (`delta_recap_cursors`, contrôles positifs) ; 7 front (`DeltaRecapInterstitial.test.tsx` — rien-si-vide, dialog+strings verbatim, chip conditionnel, checklist, ack/unmount, ack-sur-CTA, zéro emoji) + mocks ajoutés aux tests `/accueil`. Fast lane API **1526 passed** ; web **990 passed** (125 fichiers) ; mypy 0 ; tsc 0 ; mes fichiers eslint 0 warning ; RBAC 298 (2 endpoints authentifiés ajoutés, pas d'AllowAny).
- **Preuve live** (stack dev) : login session réel → `GET /me/delta-recap/` = **3 cartes** (« École Live Digest 8.5 a répondu — profil intéressant » stat 45→55 ; « 1 nouvelle école correspond à ton profil » ; « Parcoursup : la plateforme ouvre le 14 octobre 2026 », `days_until: 18` — l'exemple de l'AC — + checklist 8.3) → **SSR `/accueil`** contient l'interstitiel (« Depuis ta dernière visite », les 3 cartes, chip `45 % → 55`, « Tout vu, continuer ») → `POST /ack/` 204 → re-GET `{"cards": []}`.
- **Pièges rejoués** : (1) allauth vérifie SA table `EmailAddress`, pas `email_verified_at` — seed live corrigé ; (2) pa-web servait la **vieille** page (`.next` stale sur volume colima, file-watching) — diagnostiqué par l'absence de la ref du chunk client dans le RSC payload, résolu par `rm -rf /app/.next/*` + restart ; entre-temps deux fausses pistes (cache Next, cookies non transmis) écartées par sondes (fetch node depuis le conteneur = 200 ; logs API).
- Seed dev conservé : jalon campagne `proof-8-6` (14 oct. 2026, `notified_at` posé pour que le beat 8.3 ne l'emaile jamais) — utile pour démo ; à purger avec les seeds live 8.5.
